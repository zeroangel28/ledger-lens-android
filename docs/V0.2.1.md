# v0.2.1: new Ledger receiving addresses

Open Accounts, choose Receive for BTC or Cardano, then Generate new receiving address. This derives a child address of the imported Ledger account's public key. It does not create a new seed, request a private key or move funds. Every older address remains valid.

- BTC Native SegWit: use the next candidate on `m/84'/0'/account'/0/index`, skipping confirmed/pending transaction history. Both public providers failing stops generation; no failed lookup is interpreted as unused.
- Cardano: derive `m/1852'/1815'/account'/0/index`, retaining stake key `account/2/0`. Generation works offline and adds no Cardano API calls. The next address can already be known to another wallet using the same account.
- Previous/next controls browse issued addresses. QR, copy, share and optional Ledger address verification all use the selected address/path. Selection is saveable across screen recreation; a newly issued address becomes selected.
- Encrypt and save the issued index before displaying its address. Existing stores migrate with index 0. Original account address/public key/signing identity remain unchanged.
- Holdings discovery and transaction UTXO selection include issued receiving addresses beyond an earlier empty gap, with bounded discovery up to 1,000 addresses per branch. New address generation respects the configured unused gap and index 899 limit.
- Ethereum/TRON still receive at the imported account address. Import another Ledger account index for an additional address.

The routine Cardano daily limit and Binance market-cache/foreground price timers are unchanged. A synchronization still consists of multiple provider requests; the daily limit is not a promise of one HTTP request.

Verified locally: 40 JVM tests, 12 offline engine tests, debug APK and instrumentation APK builds, Lint with 0 errors/2 warnings. Android runtime/UI checks and Samsung installation were deferred because the user requested leaving ADB off. Real Flex nonzero-index display/receive/spend tests remain pending.
