# Ledger Lens：通知、新地址與轉帳測試

版本 v0.3.0，2026-10-09。這份手冊不會自動發送任何交易。

## 先測價格通知

1. 安裝同一開發簽章的 v0.3.0 APK，直接覆蓋更新，保留已匯入帳戶；不要為了測試清除 App 資料。
2. 開啟「設定 → 價格暴漲提醒 → 發送測試通知」，允許 Android 通知權限。通知標題必須明確寫「測試通知」。這一步不需要持倉、不查鏈、不簽署交易。
3. 如果沒有收到，點「開啟系統通知設定」，確認 Ledger Lens 與價格提醒頻道均允許通知。勿擾模式可能讓通知沒有聲音或橫幅；看通知匣是否有紀錄。
4. 啟用上漲通知，預設門檻 +3%，也可選 +5%。只有餘額已知、數量大於 0、具有可信 Binance Spot 對應的資產會監控；手動隱藏仍監控，USDT 計價基準本身不監控。沒有持倉時，測試通知仍可使用。
5. 背景檢查預設開啟，約每 15 分鐘；App 開啟時沿用每 30 秒報價。以「最近有效檢查」確認有取得可比較的資料。重開 App 應保留設定。
6. 真實提醒比較目前現貨價格與 60–61 分鐘前的 Binance 一分鐘 K 線開盤價。不是 Binance 24 小時漲幅，也不是「最近一小時最低價反彈幅度」。第一次有效檢查若已達門檻，也會通知。
7. 同幣持續高於門檻不會重複提醒；至少間隔一小時，還要觀察到回落至門檻以下後再跨過。測試通知不影響這個冷卻時間。

背景排程可另外驗證：先確定有正餘額與有效報價，記下「最近有效檢查」，正常離開 App 約 20–30 分鐘。回來前先關閉網路，再開 App 讀取保存的時間，避免前景刷新混淆結果；若時間在離開期間更新，表示背景曾完成有效檢查。之後恢復網路。若沒有更新，先檢查省電／深度休眠與通知權限，並留意排程可能延後。這項檢查不代表價格真的達到門檻。

Android WorkManager 的週期工作最低為 15 分鐘，休眠與省電會使它延後；沒有精準的到點保證。Samsung 若把 App 放入深度休眠，可能需要在電池設定移除休眠限制。不要用系統「強制停止」測背景提醒；強制停止後通常要重新開啟 App。參考 [Android 週期背景工作](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest) 與 [通知權限](https://developer.android.com/develop/ui/views/notifications/notification-permission)。

目前仍未在 Samsung 實測這版通知、背景排程或新版 UI。單元測試驗證條件與冷卻，不代表手機一定顯示橫幅。

## 不移動資金：核對新收款地址

1. 先確認已匯入正確 Ledger 帳戶與主網。BTC 此版使用 Native SegWit（`bc1q`）；Cardano 使用 Shelley base 地址（`addr1`）。ETH／TRON 要另一個地址時，連接 Ledger 匯入另一個帳戶索引。
2. 「帳戶 → 接收」，記錄原地址及完整衍生路徑，再點「產生新收款地址」。BTC 需要網路查交易歷史；Cardano 離線產生，不增加持倉 API 查詢。
3. 確認地址序號與末端索引增加，完整地址改變。QR 解碼、複製、分享的結果都必須與畫面完全相同。QR 只包含地址，沒有交易指令。
4. 解鎖 Ledger Flex、開啟對應幣種 App，以 USB 或 BLE 連接，點「在 Ledger 核對地址」。核對 Ledger 裝置上顯示的完整地址與手機一致，再批准。第一次測試可先用 USB，再重複 BLE。
5. 用上一個／下一個切換舊地址，確認舊地址仍存在。切換至舊地址後旋轉手機；關閉並重開 App，確認已產生的最新序號仍保存。
6. BTC 可斷網測失敗：產生新地址應顯示錯誤，序號不得假裝成功增加。有交易歷史的候選地址會被略過。到連續未使用地址限制時停止，先使用已有地址。Cardano 新地址不代表另一個使用同帳戶的錢包沒有用過該索引。

本功能衍生同帳戶的公鑰地址，不建立助記詞或軟體錢包私鑰。刪除／重裝 App 會失去地址序號紀錄；其他錢包找回資產時可能需要提高掃描 gap。原地址不因產生下一個地址而失效。[Ledger 的收款說明](https://www.ledger.com/academy/topics/ledger-wallet/how-to-send-receive-spend-crypto-with-ledger-wallet)也要求先在裝置螢幕核對地址。

## 真正收款與發送：小額主網測試

目前 App 的鏈、地址驗證與簽名都固定主網，**不支援用測試網幣直接操作**。例如把 `tb1` 測試地址貼進 BTC 發送表單會被拒絕。測試網支援需另外加入網路切換、路徑、節點、手續費與簽名設定；不能只更換 API URL。

使用兩個由你控制的帳戶 A、B；可以是同一 Ledger 的兩個已匯入帳戶。每次金額須高於網路的最低輸出要求，並保留足夠原生幣支付費用。先測一種原生幣，成功後再依序測其他原生幣與代幣。

1. 讓 A 產生並完成 Ledger 核對的新地址。從 B 發送一筆小額到 A；檢查交易 ID／主網區塊瀏覽器、首次鏈上確認與 A 的餘額。外部轉入 Cardano 後，普通餘額同步仍有 24 小時限制；發送前的刷新是額外允許的檢查。
2. 在 A 選資產 → 傳送，貼上或掃描 B 的完整主網地址，輸入少量數量，點「估算費用並檢查交易」。比對收款地址、資產、數量、預估費用與總扣款。
3. 先測拒絕：手機按確認後，在 Ledger **拒絕**交易。App 應顯示拒絕／失敗，沒有成功交易 ID、廣播成功或鏈上扣款。簽名未完成時拔除裝置，也不能顯示成功。
4. 重新估算，再測核准：手機確認 → Ledger 實體核對完整內容並批准 → App 驗證簽名 → **自動廣播**。Ledger 核准後不是另一個可取消的預覽階段。
5. 接受廣播先顯示待確認；首次鏈上確認後才算完成，並刷新來源帳戶一次。記錄交易 ID，查看正確鏈的瀏覽器；對照 A、B 的餘額與實際費用。刷新／重開 App 不得再次發送。
6. 最後才測「最大可傳送」：確認有預留手續費，BTC 找零／Cardano 其他代幣應留在原帳戶。用新地址收到的已確認 UTXO 必須能在估算中被發現。

| 資產 | 要額外核對的事項 |
|---|---|
| BTC | Native SegWit；收款先確認，再花費；有找零時屬於同帳戶 |
| ETH | Ethereum mainnet；保留 ETH 支付 gas |
| TRX | TRON mainnet；新收款帳戶可能有啟用成本 |
| ADA | Cardano mainnet；UTXO 與找零屬於原帳戶 |
| USDT | 選定 Ethereum ERC-20 或 TRON TRC-20；兩者是不同鏈，分別需 ETH 或 TRX 費用 |
| NIGHT | Cardano 原生資產；收款方同時收到附帶最小 ADA，畫面須與「費用」分開；其他代幣不能消失 |

如果廣播結果不明或一直待確認，先用既有交易 ID 查鏈；不要重送相同付款。未解決交易會阻擋同帳戶繼續發送。Physical Flex USB／BLE、新地址真實收款／花費、七資產轉帳均仍待使用者硬體驗證，先不要以大量資產測試。

## 電腦端不動真幣的測試

在專案資料夾使用 JDK 17 與 Android SDK 35：

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

JVM 測試覆蓋地址衍生、非零地址資產發現、通知精確門檻、冷卻與資料保存。離線 Ledger SDK 測試可在安裝 Node 22+ 後執行：

```powershell
cd signing-engine
npm ci --ignore-scripts
npm run build
npm test
```

這些測試只使用公開的確定性測試向量與模擬 Ledger 回應，沒有你的私鑰、不會廣播交易。Android instrumentation 可在專用模擬器執行 `connectedDebugAndroidTest`；不要把會清除測試資料的開發腳本套到真實手機。

另見 [實體 Flex 檢查清單](FLEX_TESTING.md) 與 [測試紀錄](VALIDATION.md)。
