# Privacy

Ledger Lens stores public account data, issued receiving-address indices, settings, cached balances/quotes, market eligibility, API credentials and transaction IDs/status/addresses/amounts. It never requests a recovery phrase or wallet private key. Android Keystore creates an encryption key for local data, unrelated to wallet keys. Removing an account deletes its local account record; public transaction history remains. Uninstalling removes local app data, including the issued-address index.

Refreshing discloses account addresses to the relevant chain service: mempool.space/Blockstream, PublicNode, Blockscout (or Alchemy when configured), TronGrid or Koios/Blockfrost. Their servers see your IP address and requested addresses. Full account xpubs stay on the phone; Bitcoin/Cardano child addresses are derived locally. Binance receives requested market symbols, not wallet addresses. API keys go only to their corresponding provider via HTTPS. Cardano holdings-query timestamps are encrypted locally to enforce the 24-hour synchronization limit; price requests are independent.

The app has no analytics, advertisements, telemetry or app-operated server. Android USB/Bluetooth permission is requested for connecting to Ledger; Android 8–11 additionally requires location permission for BLE discovery. Scan results stay in memory. Amount masking hides numbers on screen but is not authentication or screenshot protection. Local encryption does not protect an unlocked/root-compromised device or clipboard contents after you copy an address.

Starting QR scanning requests camera permission through Android. QR contents only fill a recipient address; payment amounts or contract calls in a QR do not execute. Camera images are not saved. Copy/share uses Android's clipboard/share chooser. Receiving can display an imported address without internet or Ledger. Preparing a send discloses source/recipient addresses for fee and balance queries; broadcasting sends the signed public transaction to the selected chain service. The bundled signing engine cannot access the network. Signed transaction bytes and signatures are used in memory; the persisted history contains public transaction information.

Generating a Bitcoin receiving address queries candidate and previously issued child-address transaction history through mempool.space or Blockstream. Cardano generation is local and adds no API requests. Device verification sends the selected public derivation path/address to Ledger. Original account extended public keys are not uploaded by these operations.

Opt-in price rise and fall alerts store settings, per-pair and direction crossing/cooldown state and market eligibility in a separate Keystore-encrypted file. Background WorkManager tasks read locally cached holdings to select Binance Spot pairs; they do not query blockchain holdings or submit transactions. Binance receives market symbols and minute-candle time ranges, not account keys or addresses. Notifications contain a market symbol, signed change percentage and price, with no wallet quantities or addresses. Privacy mode hides those details; lock-screen public content is generic. A user-triggered test notification contains no real-market signal. Notification delivery and background execution depend on Android permissions and power management.

Demo data is clearly labelled, not saved and does not trigger network queries. The public repository contains no personal wallet account or service credential. No recovery from cloud backup is provided because app backup is disabled.
